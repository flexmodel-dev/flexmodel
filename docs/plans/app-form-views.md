# 表单多类型视图技术方案

## 一、目标与范围

将表单的 `viewTabs` 从“表格筛选页签”扩展为完整的视图配置，支持 **表格、看板、日历、画廊、详情、层级、甘特** 七种视图。

本次已确认的产品规则：

- 页签栏增加独立的 **“＋ 新增视图”** 入口，选择类型后配置并创建。
- 最右侧齿轮改为 **“设置当前视图”**，不再编辑整组页签。
- 保留固定的“全部”表格视图，始终排在第一位，不可删除、重命名或修改类型；支持设置显示字段和默认排序。
- 不设置独立默认视图；首次进入和重新进入表单时始终打开第一个视图（即“全部”）。
- 看板、日历和甘特支持拖拽修改数据。
- 详情支持“列表＋详情”和“仅显示第一条详情”两种模式。
- 层级首期支持本表父子关系；甘特首期支持排期，不包含任务依赖、自动排程和里程碑。

实现范围以 `flexmodel-apps-ui` 和服务端 Apps 的表单、记录功能为主，复用现有字段控件、记录抽屉、查询条件、附件和审批能力。

## 二、交互与各视图能力

### 视图管理

- “＋”展示七种视图类型、图标和简短用途说明，选择后打开右侧配置抽屉。
- 配置抽屉包含名称、数据筛选、默认排序、显示字段及当前类型的专属设置。
- 新建视图允许不配置筛选条件；必需字段配置完成并保存后，持久化并切换到新视图。
- 普通视图可在设置中切换类型，保留名称、筛选、排序等通用配置，重新填写目标类型的专属配置后保存。
- 页签更多菜单提供重命名、复制、删除；支持拖拽调整顺序，“全部”固定。
- 删除当前视图后切换到“全部”视图。
- 切换视图清除记录勾选、分页位置和当前详情选择，保留当前关键词与临时高级查询。
- 共享配置仅在点击“保存”后更新；搜索、临时排序、展开状态等浏览操作不自动写入配置。

### 七种视图

以下参考明道云的常用形态，并按本次确认的范围裁剪。

| 类型                                            | 核心展示与操作                                                         | 专属配置                                     |
|-------------------------------------------------|------------------------------------------------------------------------|----------------------------------------------|
| [表格](https://help.mingdao.com/view/grid/)     | 延续现有表格、分页、勾选、排序和批量操作                               | 显示字段及顺序                               |
| [看板](https://help.mingdao.com/view/board/)    | 按字段分列，卡片点击打开详情，跨列拖拽修改分组值；各列独立加载更多     | 分组字段、卡片标题、显示字段、可选封面       |
| [日历](https://help.mingdao.com/view/calendar/) | 月／周／日切换、今天定位、跨日事件、点击事件查看详情；拖拽调整日期     | 开始字段、可选结束字段、标题、默认周期       |
| [画廊](https://help.mingdao.com/view/gallery/)  | 图片封面卡片网格，自适应列数，点击打开详情，支持分页                   | 封面字段、标题、显示字段、图片裁切方式       |
| [详情](https://help.mingdao.com/view/details/)  | 左侧分页记录列表＋右侧内嵌详情，或直接展示排序后的第一条详情           | 展示模式、列表摘要字段                       |
| [层级](https://help.mingdao.com/view/org/)      | 层级树和树形表格两种形态，支持展开收起、节点详情                       | 关联本表的单条引用字段、展示形态、显示字段   |
| [甘特](https://help.mingdao.com/view/gantt/)    | 左侧任务列表＋右侧时间轴，日／周／月刻度、今天定位、整体移动与两端拉伸 | 开始字段、结束字段、标题、显示字段、默认刻度 |

补充规则：

- 看板支持 `PICKLIST / SELECT / CLASSIFICATION / BOOL / REFERENCE` 等单值字段。选项按定义顺序排列，布尔显示“是／否”，引用按实际分组分页展示；空值进入“未分组”。
- 看板同列拖动不保存手工卡片顺序，卡片顺序由视图排序决定。
- 只读字段和内置字段可用于展示、分组，但不能通过拖拽修改。
- 画廊允许没有封面字段；无图片、非图片附件或图片加载失败时显示统一占位。
- 详情沿用表单布局、子表单及记录动态，支持编辑、删除和审批操作。窄屏下切换为列表与详情分步浏览。
- 层级使用单条自引用字段识别父节点，不支持跨表层级或拖拽调整父子关系。
- 日历和甘特提供未排期记录入口。甘特中缺少任一起止值的记录归入未排期列表，非法日期范围单独提示。
- 视图显示字段只控制列表、卡片等摘要区域；完整详情继续使用表单布局。

## 三、配置模型与服务端接口

### 配置模型

继续使用 `viewTabs` 保存完整视图定义：

```ts
type AppViewType =
  | 'TABLE'
  | 'KANBAN'
  | 'CALENDAR'
  | 'GALLERY'
  | 'DETAIL'
  | 'HIERARCHY'
  | 'GANTT'

interface AppFormViewTab {
  id: string
  label: string
  type: AppViewType
  filter: AppFormViewFilter | null
  sort: { field: string; order: 'ASC' | 'DESC' } | null
  displayFields: string[]
  config: AppViewConfig
}
```

- `AppViewConfig` 按 `type` 定义前后端对应的类型，包含第二节列出的专属配置，避免使用无约束配置对象。
- 通用筛选复用现有条件控件和校验能力，支持根节点 `_and` 或 `_or`，最多 10 个条件；`null` 表示不筛选。
- 保留名称长度、ID 唯一性等现有约束，最多允许 20 个自定义视图，“全部”不计入限额。
- “全部”使用保留 ID `all`，固定 `TABLE` 类型和空筛选；新表单初始化时生成，始终排在第一位。
- 未配置默认排序时使用创建时间倒序；分页查询追加 ID 作为稳定排序条件。
- 专属配置校验字段存在性和类型：层级必须自引用；日期起止字段必须同为 `DATE` 或同为 `DATETIME`。
- 删除仍被视图引用的字段时阻止操作，并返回相关视图名称，要求先调整视图配置。

### 保存接口

扩展现有接口：

```http
PATCH /api/apps/{appId}/forms/{formName}
```

```json
{
  "viewTabs": []
}
```

一次保存原子更新完整视图集合，校验后返回最新表单。服务端保证固定视图存在；保存失败时前端保留草稿。

### 视图数据查询

增加：

```http
POST /api/apps/{appId}/forms/{formName}/views/{viewId}/query
```

请求包含分页、关键词、临时高级查询、临时排序，以及查询范围 `scope`：

| scope                          | 用途                                     |
|--------------------------------|------------------------------------------|
| `RECORDS`                      | 表格、画廊、详情的记录分页               |
| `GROUPS`                       | 看板分组及筛选后的分组数量               |
| `GROUP_RECORDS`                | 指定看板列的记录分页，分组值允许显式为空 |
| `RANGE`                        | 日历、甘特指定时间窗口内的记录           |
| `UNSCHEDULED`                  | 未排期及日期异常记录分页                 |
| `TREE_ROOTS` / `TREE_CHILDREN` | 层级根节点或指定节点的下级分页           |

接口按 scope 返回明确类型的分页结果，统一包含 `list`、`total`；树节点补充是否存在下级，记录结果补充是否允许拖拽及禁用原因。

查询规则：

- 服务端组合“视图筛选 AND 关键词 AND 临时查询 AND 当前范围”，禁止前端只过滤当前页。
- 看板数量通过带相同筛选的聚合查询计算，不能使用当前已加载卡片数代替。
- 表格、画廊、详情和看板列默认每页 30 条；底层单次查询保持最多 200 条。
- 日历按事件与窗口是否相交查询，包含起点在窗口外的跨期事件；甘特同时按时间窗口和记录分页查询。
- 日历分批加载窗口内事件，首次最多自动加载 1000 条；超出时明确显示已加载数量、总量和“继续加载”，不静默截断。
- 层级在服务端构建筛选结果的轻量父子拓扑，分支分页返回。父节点未命中筛选或已不存在时，子节点作为根节点展示；循环、自引用归入异常关联并阻断递归。
- 复用现有记录查询、引用值展开和数据投影逻辑，新增接口不复制另一套记录读取实现。

空分组、未排期和根节点查询需要可靠的空值条件：补齐 SQL 条件渲染中 `_eq: null`／`_ne: null` 对应的 `IS NULL`／`IS NOT NULL`
，并增加引擎回归测试。

### 拖拽写入

增加视图动作接口：

```http
POST /api/apps/{appId}/forms/{formName}/views/{viewId}/records/{recordId}/move
```

请求提交变化字段的原值和目标值；服务端根据视图配置限定允许修改的字段：

- 看板仅修改分组字段。
- 日历移动开始时间；存在结束值时保持时长同步移动。
- 甘特整体移动保持时长，拉伸只改变对应端点。
- 使用现有字段校验、记录更新、操作历史和事务能力；写入前重新检查字段可写性、审批锁定状态及日期范围。
- 在事务内核对原值；目标字段已被其他请求修改时返回 `409`，由前端恢复并刷新。
- `DATE` 按自然日处理；`DATETIME` 沿用现有不带时区的本地时间语义，避免通过 UTC 转换改变日期。
- 日期型结束值包含当日；日历组件需要的排他结束边界在适配层转换。日期时间型要求结束晚于开始。
- 写入期间禁止重复拖拽；失败恢复原位置并提示，成功后刷新记录、分组数量和所属范围。

## 四、前端结构与实施顺序

将 `RecordList` 调整为视图页面容器，负责表单加载、当前视图、共享查询、工具栏和记录操作，各视图只负责展示与专属交互。

主要拆分：

- **视图栏与配置**：类型注册表、视图栏、新增菜单、当前视图设置抽屉；注册表统一管理名称、图标、默认配置和渲染组件。
- **查询与状态**：统一视图查询 Hook；看板分列状态、日历时间窗口和层级展开状态按视图隔离，处理切换时旧请求覆盖问题。
- **展示组件**：复用表格、分页器、字段格式化、附件预览和引用值组件；看板与画廊复用记录卡片。
- **详情复用**：从现有统一记录抽屉提取可内嵌的记录面板，让抽屉和详情视图共享字段、子表单、编辑、审批与记录动态。
- **日历与时间轴**：日历采用 FullCalendar Standard 的 React
  组件及月／周／日、交互能力，使用其[标准插件](https://fullcalendar.io/license)；看板复用现有
  dnd-kit，甘特使用共享日期计算与轻量时间轴，不引入任务依赖引擎。层级树复用已有 ECharts，树形表格复用表格组件。
- **整体样式**：使用现有主题 token、Lucide 图标和 Drawer，适配浅色、深色与窄屏，滚动限定在各视图内容区。

按一个“表单多类型视图”功能顺序实施：

1. 配置模型、公共校验、默认视图和设置交互。
2. 查询接口与表格、画廊、详情视图。
3. 看板分组、分列分页及拖拽写入。
4. 日历、甘特的范围查询与日期交互。
5. 层级拓扑、异常关联处理及整体联调。

同步覆盖应用包导入导出、内置模板、表单设计器状态保存和 MCP 契约说明，确保所有表单读写路径保留完整视图配置。Excel
筛选导出复用共享筛选与排序规则；日历窗口、树展开和已加载卡片范围不自动限制 Excel 导出。

## 五、验收、边界与交付

### 验收场景

- 七种视图均能创建、设置、切换、复制、排序和删除；刷新后配置一致。
- “＋”仅负责新增，齿轮只设置当前视图；创建表单时，自动新增“全部”视图，进入表单先打开第一个视图。
- 无筛选视图、全部／任一条件、关键词和临时高级查询正确叠加，数量与结果一致。
- 使用超过 200 条的数据验证分组计数、后续分页、跨期事件和多层树，排除仅处理首批记录的问题。
- 看板验证空值、布尔 `false`、引用值和只读分组；拖拽后记录更新且其他视图可见。
- 日历验证全天、日期时间、跨月事件及拖动后时长保持；甘特验证整体移动、双端拉伸和未排期。
- 详情两种模式、空记录、编辑后不再匹配筛选、删除当前记录及审批锁定均正确处理。
- 层级验证父节点缺失、父节点被筛选、自引用、循环关联和分支分页。
- 写入失败、并发冲突及视图切换中的请求竞态不会留下错误位置或旧数据。
- 应用包导出再导入后，七种视图及顺序完整恢复；内置模板通过新契约校验。
- 检查浅色、深色和窄屏，避免外层重复滚动及工具栏遮挡。

### 实施后的验证

- Apps UI：构建、Vitest，以及覆盖视图管理和实际拖拽操作的 Playwright 测试。
- 服务端：视图配置、范围查询、分组统计、拖拽校验与应用包相关定向测试。
- 全模块执行不带 `clean` 的编译，并运行引擎测试；本方案不要求执行 `init.sh`。
- 使用真实后端完成“创建视图→保存→刷新→拖拽更新→切换视图核对→导出导入”的冒烟验证。

### 默认边界与交付物

- 配置继续为表单级共享配置，沿用现有访问控制，不增加个人视图或新的视图权限体系。
- 首期不包含地图、资源、跨表层级、任务依赖、自动排程、视图分享和图片导出。
- 按项目约定不提供旧配置兼容层或历史迁移；随项目发布的模板与测试数据同步更新。
- 实施时保留工作区已有修改，不自动提交代码。
- 交付技术方案文档、完整实现与验证证据，并更新 `feature_list.json` 和 `progress.md`。
